---
title: "Прямая загрузка аудио"
description: "Подготовка загрузки, выбор модели для русской речи, отправка файла и получение результата по ID задачи."
---

Прямая загрузка доступна аккаунтам, для которых она подключена. Сначала запросите разрешение, затем отправьте аудиофайл по выданному HTTPS-адресу. За результатом обращайтесь к основному API Palatine Speech.

## 1. Подготовьте загрузку

Создайте UUID для новой записи. Сохраните его до получения результата и передавайте в заголовке `Idempotency-Key`. Для русской речи укажите модель `palatine_large_ru_v1`. В некоторых случаях, например для записи на другом языке или при использовании словаря, сервис может выбрать резервную модель.

```bash
curl -sS https://api.palatine.ru/api/v1/asr-upload/prepare \
  -H "Authorization: Bearer $PALATINE_API_KEY" \
  -H "Idempotency-Key: $UPLOAD_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"model":"palatine_large_ru_v1","language":"ru"}'
```

`model` обязателен. Поля `language`, `fast_inference` и `dictionary` опциональны. По умолчанию `fast_inference` включён. Поле `dictionary` принимает массив строк по [правилам словаря терминов](/documentation/quick_start/dictionary). Для непустого словаря оставьте `fast_inference=true`.

При статусе `prepared` ответ содержит:

| Поле | Как использовать |
| --- | --- |
| `operation_id` | Сохраните как ID задачи для опроса результата. |
| `upload_url` | Отправьте файл по этому адресу целиком, включая домен и путь. |
| `upload_token` | Используйте как Bearer-токен для загрузки файла. |
| `expires_at` | Отправьте файл до этого времени. Разрешение на загрузку действует пять минут. |
| `max_bytes` | Максимальный размер файла для этой операции, в байтах. |

## 2. Отправьте файл

Возьмите `UPLOAD_URL` и `UPLOAD_TOKEN` из ответа на подготовку. Отправьте один multipart-файл в поле `file`.

```bash
curl -sS -X POST "$UPLOAD_URL" \
  -H "Authorization: Bearer $UPLOAD_TOKEN" \
  -F 'file=@audio.mp3'
```

HTTP `202` возвращает тот же `operation_id` и один из трёх статусов. При `scheduled` или `closed` переходите к опросу результата. При `receiving` предыдущая попытка ещё передаёт файл: подождите и повторите подготовку с тем же UUID.

## 3. Получите результат

Подставьте `operation_id` в адрес запроса. Для статуса используйте обычный API-ключ Palatine Speech.

```bash
curl -sS "https://api.palatine.ru/api/v1/transcribe/task_status/${OPERATION_ID}?response_format=json" \
  -H "Authorization: Bearer $PALATINE_API_KEY"
```

`pending` означает, что обработка продолжается. При `success` расшифровка доступна в `data`. При `error` подробности возвращаются в поле `error`. Подробнее об опросе статуса в [руководстве по polling API](/documentation/technical_information/polling_principles).

## Повторите попытку после обрыва

- Если ответ на подготовку или загрузку потерялся, повторите подготовку с прежним UUID, тем же API-ключом и параметрами. Повтор в течение 24 часов возвращает ID исходной операции. По истечении этого срока повтор с тем же UUID может создать новую операцию. Если ответ снова содержит `prepared`, отправьте файл по полученному разрешению. Если статус `receiving`, подождите и повторите подготовку.
- Если загрузка вернула `410`, повторите подготовку с прежним UUID. После статуса `expired` создайте новый UUID для повторной отправки записи.
- Если подготовка вернула `409`, проверьте, что повтор отправлен с теми же параметрами. При `429` или `503` подождите и учитывайте `Retry-After`, если сервер его вернул.
