TTS преобразует текст в речь и возвращает готовый WAV либо поток звука.
Через WebSocket текст можно передавать постепенно, например по мере подготовки
ответа голосового бота.

<Warning>
API синтеза речи находится в платной бета-версии. SLA для беты не объявлен.
</Warning>

Цена, голоса и ограничения этой страницы относятся к TTS API.
Palatine Live имеет собственные условия.

## Стоимость и списания

Стандартная цена — **1 ₽ / 1000 символов**. Пробелы и пунктуация учитываются;
текст нормализуется в NFC, затем считаются Unicode code points. Сумма округляется
вверх до копейки один раз за операцию: 250 символов — 0,25 ₽, 500 — 0,50 ₽,
11 — 0,02 ₽. Для индивидуального тарифа действует его цена.

Перед синтезом сумма резервируется на балансе: сначала бонусном, затем основном.
При успешном завершении оплачивается принятый к синтезу текст. Для WebSocket
резерв соответствует `max_characters`; неиспользованный остаток возвращается.
Технический отказ возвращает весь резерв. Недостаток средств возвращает `402`.

При отмене PCM/SSE/WS до первой подтверждённой отправки звука резерв возвращается.
После неё оплачивается текст, уже принятый к синтезу, включая поставленные в очередь
фразы. Буферный WAV/PCM оплачивается после сохранения готового результата; потеря
соединения после этого не отменяет оплату. Для повторной отправки используйте
[`Idempotency-Key`](#ошибки-и-повтор-запросов).

Если денежный результат ещё уточняется, состояние операции — `reconciling`.
Проверяйте [состояние той же операции](#состояние-операции), не запускайте её заново
с новым ключом.

## Подключение

Используйте обычный API-ключ Palatine Speech из личного кабинета.

В примерах задайте `SPEECH_API_KEY` в окружении серверного приложения и используйте
базовый адрес:

```bash
TTS_BASE_URL="https://api.palatine.ru"
```

Передавайте ключ в заголовке `Authorization: Bearer …`. Для WebSocket также укажите
подпротокол `palatine.tts.v1`. Ключ не следует помещать в URL, исходный код браузера
или журналы запросов.

## Получить WAV

Сохраните уникальный ключ этой операции и используйте его при повторе:

```bash
TTS_REQUEST_ID="tts-request-20261107-001"
curl --fail-with-body --silent --show-error \
  "$TTS_BASE_URL/api/v1/audio/speech" \
  -H "Authorization: Bearer $SPEECH_API_KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $TTS_REQUEST_ID" \
  -d '{
    "model": "palatine-tts-beta",
    "input": "Здравствуйте! Это пример синтеза речи.",
    "voice": "palatine-male-1",
    "response_format": "wav"
  }' \
  --dump-header response.headers \
  --output speech.wav
```

Успешный ответ — `200`, `Content-Type: audio/wav`. Файл содержит один канал,
16-битный PCM с частотой 24 000 Гц. Заголовок `X-Operation-ID` содержит идентификатор
операции, `X-Audio-Rate` — частоту звука.

### Параметры запроса

| Поле | Значение |
|------|----------|
| `model` | Обязательное значение `palatine-tts-beta` |
| `input` | Непустой текст, до 500 символов Unicode после нормализации NFC |
| `voice` | Голос из таблицы ниже; по умолчанию `palatine-male-1` |
| `response_format` | `wav` (по умолчанию) или `pcm` |
| `stream` | `false` (по умолчанию); для потока — `true` вместе с `response_format: "pcm"` |
| `stream_format` | `audio` (по умолчанию) или `sse`; `sse` требует `stream: true` |

Неизвестные поля отклоняются. Управление темпом, интонацией и клонирование голоса
в этом API не предусмотрены.

| `voice` | Голос |
|---------|-------|
| `palatine-male-1` | Мужской 1 (по умолчанию) |
| `palatine-male-2` | Мужской 2 |
| `palatine-male-3` | Мужской 3 |
| `palatine-female-1` | Женский 1 |

В TTS API доступны четыре голоса.

## Потоковый вывод

В HTTP-запросе текст передаётся целиком. Звук поступает частями в формате
**PCM16 little-endian, mono, 24 000 Гц**, без WAV-заголовка.

<Tabs>
  <Tab title="PCM">

```bash
curl --fail-with-body --silent --show-error --no-buffer \
  "$TTS_BASE_URL/api/v1/audio/speech" \
  -H "Authorization: Bearer $SPEECH_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "palatine-tts-beta",
    "input": "Здравствуйте! Звук поступает по мере генерации.",
    "voice": "palatine-male-1",
    "response_format": "pcm",
    "stream": true
  }' \
  --dump-header response.headers \
  --output speech.pcm
```

Ответ имеет тип `audio/pcm`. Для воспроизведения задайте плееру параметры PCM
выше. Границы сетевых чанков не являются границами фраз.

Завершение HTTP-потока само по себе не доказывает успех: сервер уже мог отправить
`200`, а затем прервать синтез. Проверьте [состояние операции](#состояние-операции).

  </Tab>
  <Tab title="SSE">

```bash
curl --fail-with-body --silent --show-error --no-buffer \
  --dump-header response.headers \
  "$TTS_BASE_URL/api/v1/audio/speech" \
  -H "Authorization: Bearer $SPEECH_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "palatine-tts-beta",
    "input": "Здравствуйте! Это поток событий со звуком.",
    "voice": "palatine-male-1",
    "response_format": "pcm",
    "stream": true,
    "stream_format": "sse"
  }'
```

Ответ имеет тип `text/event-stream`:

```text
event: audio.delta
data: {"audio":"BASE64_PCM"}

event: done
data: {"operation_id":"tts_..."}
```

Декодируйте `audio` из Base64 и воспроизводите полученный PCM по порядку.
Успех подтверждает терминальное событие `done`. При ошибке после начала потока
вместо него приходит `error`, например:

```text
event: error
data: {"code":"synthesis_failed"}
```

Отсутствие `done` при закрытии соединения также требует проверки состояния
операции. Сам статус HTTP `200` не подтверждает полный синтез.

  </Tab>
</Tabs>

Чтобы отменить HTTP-синтез, закройте соединение. Воспроизведение уже полученного
звука останавливает ваше приложение. Частично воспроизведённый ответ не следует
автоматически повторять с начала.

## WebSocket: текст по частям

Адрес — `wss://api.palatine.ru/api/v1/audio/speech/stream`. Передайте обычный
API-ключ Speech в заголовке Bearer и подпротокол `palatine.tts.v1`.
Используйте серверный WS-клиент с поддержкой заголовка `Authorization`;
браузерное приложение подключайте через свой сервер. Query-параметры не допускаются.
Сервер начинает соединение событием `session.ready`.

Все команды — JSON с полями `type` и уникальным `event_id`. Пример одной реплики:

```jsonl
{"type":"session.configure","event_id":"config-1","model":"palatine-tts-beta","voice":"palatine-male-1"}
{"type":"utterance.start","event_id":"start-1","utterance_id":"reply-1","max_characters":100}
```

Дождитесь `utterance.started`, затем добавьте законченную фразу и передайте её
в синтез командой `text.flush`:

```jsonl
{"type":"text.append","event_id":"append-1","utterance_id":"reply-1","text":"Здравствуйте! "}
{"type":"text.flush","event_id":"flush-1","utterance_id":"reply-1"}
```

Дождитесь `segment.done`, чтобы не переполнить очередь, и отправьте следующую
фразу. `text.done` передаст оставшийся текст и завершит ввод этой реплики:

```jsonl
{"type":"text.append","event_id":"append-2","utterance_id":"reply-1","text":"Чем я могу помочь?"}
{"type":"text.done","event_id":"done-1","utterance_id":"reply-1"}
```

Границы фраз задаёт клиент; `text.append` сам по себе не запускает озвучку.
Объединяйте небольшие фрагменты текста: отдельная команда на каждый токен
может быстро исчерпать лимиты WS-команд.

Сервер присылает `audio.delta` с Base64 PCM, `operation_id`, `utterance_id`,
`segment_id` и возрастающим `seq`. Воспроизводите звук в этом порядке.
Успешное окончание всей реплики — `utterance.done`; `segment.done` завершает
только одну фразу. Команды также подтверждаются событиями `input.ack`.

Для перебивания отправьте:

```json
{"type":"utterance.cancel","event_id":"cancel-1","utterance_id":"reply-1"}
```

Немедленно остановите локальный плеер, отбросьте его буфер и игнорируйте поздние
`audio.delta` отменённой операции. Перед следующей репликой дождитесь терминального
события этой операции: `utterance.cancelled`, `utterance.done` или
`utterance.failed`. Если завершение уже получено, отдельное `utterance.cancelled`
может не прийти: отмена и окончание синтеза могли совпасть.
При `utterance.failed` или `error` обработайте отказ; сервер может отменить
текущую реплику после некорректной команды.

Для следующего ответа выберите новый `utterance_id` и новые `event_id`.
Одна реплика считается одной операцией: фрагменты `text.append` не обновляют
квоты и не начинают новый лимит текста. `max_characters` резервирует максимальный
суммарный объём реплики и должен быть от 1 до 500.

## Состояние операции

Сохраните идентификатор операции из HTTP-заголовка `X-Operation-ID` (включая SSE)
или поля `operation_id` в WS. Подставьте его в `OPERATION_ID` и проверьте состояние
после PCM-потока, при потере соединения или статусе `reconciling`:

```bash
curl --fail-with-body --silent --show-error \
  "$TTS_BASE_URL/api/v1/audio/operations/$OPERATION_ID" \
  -H "Authorization: Bearer $SPEECH_API_KEY"
```

`state: "completed"` подтверждает успех. `running` и `reconciling` требуют дальнейшей
проверки; `failed`, `cancelled` и `expired` не означают успешный результат.
`committed` — число принятых к синтезу символов, `pcm` — число байтов выходного PCM.
Денежный результат может уточняться после синтеза; общий срок расчёта не гарантирован.
Проверять операцию можно любым действующим ключом того же аккаунта;
операция другого аккаунта возвращает `404`.

## Ограничения беты

Профиль предназначен для короткой озвучки. Квоты суммируются по всем ключам
аккаунта, HTTP-запросам и WS-репликам.

| Ограничение | Значение |
|-------------|----------|
| Текст HTTP-запроса или одной WS-реплики | До 500 символов |
| Начало операций аккаунта | До 2 в минуту, интервал не меньше 30 секунд |
| Текст аккаунта | До 5 000 символов в сутки UTC |
| Одновременные операции аккаунта | 1 |
| Таймаут HTTP-синтеза или WS-реплики | 40 секунд |
| Суммарный бюджет синтеза одной операции | 30 секунд |
| Звук одной операции | До 60 секунд |
| WS-фраза между `text.flush` / `text.done` | До 200 символов; до 8 фраз в реплике |
| WS-соединение | До 15 минут; ожидание следующей команды — до 60 секунд |
| WS-команды | До 30 в секунду; до 256 уникальных `event_id` за соединение |
| Размер HTTP-тела или WS-команды | До 8 КиБ |

Для WebSocket таймаут реплики отсчитывается от `utterance.start`, включая
ожидание текста и очереди. Более долгий срок соединения не продлевает реплику;
разбиение текста на фразы не обновляет её бюджет синтеза.

Дополнительно действуют общие ограничения нагрузки сервиса. Увеличение числа
соединений или разбиение текста на фрагменты их не обходит. Отмена после начала
озвучки также не обнуляет лимит частоты.

## Ошибки и повтор запросов

| HTTP-код | Действие |
|----------|----------|
| `400` / `422` | Проверьте параметры, голос, модель и размер текста |
| `401` | Проверьте API-ключ Speech и его активность |
| `402` | Недостаточно средств или достигнут денежный лимит аккаунта |
| `403` | Проверьте API-ключ и доступность бета-версии API |
| `404` | Проверьте идентификатор операции и аккаунт, которому она принадлежит |
| `409` | Проверьте состояние исходной операции и правила повтора ниже |
| `413` | Уменьшите тело запроса |
| `429` | Доступ занят или исчерпана квота; учитывайте `Retry-After` |
| `502` / `503` | Сервис временно недоступен, занят или синтез не удался; учитывайте `Retry-After`, если он есть |

Для защиты от случайной повторной отправки HTTP можно передать
один заголовок `Idempotency-Key` длиной от 1 до 128 печатных ASCII-символов.
Повтор завершённого буферного WAV/PCM с тем же ключом и параметрами возвращает
тот же результат до истечения 15 минут без нового списания. Незавершённая операция,
изменённые параметры, истёкший результат или повтор потокового запроса получают `409`. Сохраняйте `X-Operation-ID` первого запроса для
проверки его состояния. Ключ идемпотентности действует в пределах аккаунта,
включая запросы с другими его API-ключами.

Ошибка может возникнуть и после начала потока: обрабатывайте терминальные события
SSE/WS и состояние операции, а не только код HTTP. При закрытии WebSocket с кодом
`1008` проверьте API-ключ, подпротокол и URL без query-параметров.
`1013` означает временную недоступность; `1009` — слишком большое сообщение.
При отзыве ключа или отключении сервиса уже открытое соединение может быть закрыто.
Формат HTTP-сообщения об ошибке может различаться: обработку отказа стройте по
HTTP-коду, не полагаясь на конкретный текст или внутренний код ошибки.
