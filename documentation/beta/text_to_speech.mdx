TTS преобразует текст в речь и возвращает готовый WAV либо поток звука.
Через WebSocket текст можно передавать постепенно, например по мере подготовки
ответа голосового бота.

<Warning>
Это закрытый технический тест без оплаты. Подключение доступно участникам теста
через VPN. Адрес стенда и отдельный тестовый токен выдаёт команда Palatine;
у неё же можно уточнить готовность подключения. Ключи основного Speech API здесь
не используются. Публичный запуск,
платный доступ и SLA пока не заявлены.
</Warning>

## Подключение

В примерах `TTS_BASE_URL` — выданный адрес стенда без завершающего `/`,
`TTS_BETA_TOKEN` — отдельный токен участника. Передавайте его в заголовке
`Authorization: Bearer …` из серверного приложения. Для WebSocket также укажите
этот заголовок и подпротокол `palatine.tts.v1`.

Токен не следует помещать в URL, исходный код браузера или журналы запросов.
Для ручной проверки можно пользоваться выданным тестовым интерфейсом.

## Получить WAV

```bash
curl --fail-with-body --silent --show-error \
  "$TTS_BASE_URL/api/v1/audio/speech" \
  -H "Authorization: Bearer $TTS_BETA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "palatine-tts-beta",
    "input": "Здравствуйте! Это пример синтеза речи.",
    "voice": "ru-default",
    "response_format": "wav"
  }' \
  --dump-header response.headers \
  --output speech.wav
```

Успешный ответ — `200`, `Content-Type: audio/wav`. Файл содержит один канал,
16-битный PCM с частотой 24 000 Гц. Заголовок `X-Operation-ID` содержит идентификатор
операции, `X-Audio-Rate` — частоту звука.

### Параметры запроса

| Поле | Значение |
|------|----------|
| `model` | Обязательное значение `palatine-tts-beta` |
| `input` | Непустой текст, до 500 символов Unicode после нормализации NFC |
| `voice` | Голос из таблицы ниже; по умолчанию `ru-default` |
| `response_format` | `wav` (по умолчанию) или `pcm` |
| `stream` | `false` (по умолчанию); для потока — `true` вместе с `response_format: "pcm"` |
| `stream_format` | `audio` (по умолчанию) или `sse`; `sse` требует `stream: true` |

Неизвестные поля отклоняются. Управление темпом, интонацией и клонирование голоса
в этом API не предусмотрены.

| `voice` | Выбор голоса |
|---------|--------------|
| `ru-default` | Голос по умолчанию |
| `palatine-neutral` | Второе имя голоса `ru-default` |
| `palatine-serena` | Дополнительный тембр |
| `palatine-aiden` | Дополнительный тембр |
| `palatine-ru` | Дополнительный тембр |

Два имени обозначают один и тот же голос: всего доступны четыре разных тембра.
Выбор в демке Palatine Live может отличаться от списка TTS API.

## Потоковый вывод

В HTTP-запросе текст передаётся целиком. Звук поступает частями в формате
**PCM16 little-endian, mono, 24 000 Гц**, без WAV-заголовка.

<Tabs>
  <Tab title="PCM">

```bash
curl --fail-with-body --silent --show-error --no-buffer \
  "$TTS_BASE_URL/api/v1/audio/speech" \
  -H "Authorization: Bearer $TTS_BETA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "palatine-tts-beta",
    "input": "Здравствуйте! Звук поступает по мере генерации.",
    "voice": "ru-default",
    "response_format": "pcm",
    "stream": true
  }' \
  --dump-header response.headers \
  --output speech.pcm
```

Ответ имеет тип `audio/pcm`. Для воспроизведения задайте плееру параметры PCM
выше. Границы сетевых чанков не являются границами фраз.

Завершение HTTP-потока само по себе не доказывает успех: сервер уже мог отправить
`200`, а затем прервать синтез. Запишите `X-Operation-ID` в `OPERATION_ID`
и проверьте состояние:

```bash
curl --fail-with-body --silent --show-error \
  "$TTS_BASE_URL/api/v1/audio/operations/$OPERATION_ID" \
  -H "Authorization: Bearer $TTS_BETA_TOKEN"
```

Успех обозначается `state: "completed"`. Пока состояние `running`, операция
не завершена; `failed`, `cancelled` или `expired` не означают успешный результат.
Поле `committed` содержит число принятых к синтезу символов, `pcm` — число байтов
выходного PCM.

  </Tab>
  <Tab title="SSE">

```bash
curl --fail-with-body --silent --show-error --no-buffer \
  --dump-header response.headers \
  "$TTS_BASE_URL/api/v1/audio/speech" \
  -H "Authorization: Bearer $TTS_BETA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "palatine-tts-beta",
    "input": "Здравствуйте! Это поток событий со звуком.",
    "voice": "ru-default",
    "response_format": "pcm",
    "stream": true,
    "stream_format": "sse"
  }'
```

Ответ имеет тип `text/event-stream`:

```text
event: audio.delta
data: {"audio":"BASE64_PCM"}

event: done
data: {"operation_id":"tts_..."}
```

Декодируйте `audio` из Base64 и воспроизводите полученный PCM по порядку.
Успех подтверждает терминальное событие `done`. При ошибке после начала потока
вместо него приходит `error`, например:

```text
event: error
data: {"code":"synthesis_failed"}
```

Отсутствие `done` при закрытии соединения также требует проверки состояния
операции. Сам статус HTTP `200` не подтверждает полный синтез.

  </Tab>
</Tabs>

Чтобы отменить HTTP-синтез, закройте соединение. Воспроизведение уже полученного
звука останавливает ваше приложение. Частично воспроизведённый ответ не следует
автоматически повторять с начала.

## WebSocket: текст по частям

Путь — `/api/v1/audio/speech/stream`. Используйте `ws://` для выданного
HTTP-адреса или `wss://` для HTTPS, заголовок Bearer и подпротокол
`palatine.tts.v1`. Сервер начинает соединение событием `session.ready`.

Все команды — JSON с полями `type` и уникальным `event_id`. Пример одной реплики:

```jsonl
{"type":"session.configure","event_id":"config-1","model":"palatine-tts-beta","voice":"ru-default"}
{"type":"utterance.start","event_id":"start-1","utterance_id":"reply-1","max_characters":100}
```

Дождитесь `utterance.started`, затем добавьте законченную фразу и передайте её
в синтез командой `text.flush`:

```jsonl
{"type":"text.append","event_id":"append-1","utterance_id":"reply-1","text":"Здравствуйте! "}
{"type":"text.flush","event_id":"flush-1","utterance_id":"reply-1"}
```

Дождитесь `segment.done`, чтобы не переполнить очередь, и отправьте следующую
фразу. `text.done` передаст оставшийся текст и завершит ввод этой реплики:

```jsonl
{"type":"text.append","event_id":"append-2","utterance_id":"reply-1","text":"Чем я могу помочь?"}
{"type":"text.done","event_id":"done-1","utterance_id":"reply-1"}
```

Границы фраз задаёт клиент; `text.append` сам по себе не запускает озвучку.

Сервер присылает `audio.delta` с Base64 PCM, `operation_id`, `utterance_id`,
`segment_id` и возрастающим `seq`. Воспроизводите звук в этом порядке.
Успешное окончание всей реплики — `utterance.done`; `segment.done` завершает
только одну фразу. Команды также подтверждаются событиями `input.ack`.

Для перебивания отправьте:

```json
{"type":"utterance.cancel","event_id":"cancel-1","utterance_id":"reply-1"}
```

Немедленно остановите локальный плеер, отбросьте его буфер и игнорируйте поздние
`audio.delta` отменённой операции. Перед следующей репликой дождитесь терминального
события этой операции: `utterance.cancelled`, `utterance.done` или
`utterance.failed`. Если завершение уже получено, отдельное `utterance.cancelled`
может не прийти: отмена и окончание синтеза могли совпасть.
При `utterance.failed` или `error` обработайте отказ; сервер может отменить
текущую реплику после некорректной команды.

Для следующего ответа выберите новый `utterance_id` и новые `event_id`.
Одна реплика считается одной операцией: фрагменты `text.append` не обновляют
квоты и не начинают новый лимит текста. `max_characters` резервирует максимальный
суммарный объём реплики и должен быть от 1 до 500.

## Ограничения теста

Текущий профиль предназначен для короткой озвучки. Все участники используют
общий тестовый доступ, поэтому одновременно начатая чужая операция или исчерпанная
квота могут временно заблокировать ваш запрос.

| Ограничение | Значение |
|-------------|----------|
| Текст HTTP-запроса или одной WS-реплики | До 500 символов |
| Начало операций через общий тестовый доступ | До 2 в минуту, интервал не меньше 30 секунд |
| Текст через общий тестовый доступ | До 5 000 символов в сутки UTC |
| Одновременные операции через общий тестовый доступ | 1 |
| Звук одной операции | До 60 секунд |
| WS-фраза между `text.flush` / `text.done` | До 200 символов; до 8 фраз в реплике |
| WS-соединение | До 15 минут; ожидание следующей команды — до 60 секунд |
| Размер HTTP-тела или WS-команды | До 8 КиБ |

Дополнительно действуют общие ограничения нагрузки сервиса. Увеличение числа
соединений или разбиение текста на фрагменты их не обходит. Отмена после начала
озвучки также не обнуляет лимит частоты.

## Ошибки и повтор запросов

| HTTP-код | Действие |
|----------|----------|
| `400` | Проверьте параметры, голос, модель и размер текста |
| `401` | Проверьте отдельный токен беты |
| `403` | Уточните доступность теста и разрешённый источник запроса |
| `404` | Проверьте идентификатор операции и доступ к ней |
| `409` | Операция с таким ключом уже существует |
| `413` | Уменьшите тело запроса |
| `429` | Доступ занят или исчерпана квота; учитывайте `Retry-After` |
| `503` | Сервис занят, обновляется или синтез не удался; учитывайте `Retry-After`, если он есть |

Для защиты от случайной повторной отправки HTTP можно передать
`Idempotency-Key` длиной до 128 символов. Повтор с тем же ключом получает `409`,
а не повторную копию аудио. Сохраняйте `X-Operation-ID` первого запроса для
проверки его состояния.

Ошибка может возникнуть и после начала потока: обрабатывайте терминальные события
SSE/WS и состояние операции, а не только код HTTP. При закрытии WebSocket с кодом
`1008` проверьте токен, подпротокол, URL без query-параметров и доступность теста.
